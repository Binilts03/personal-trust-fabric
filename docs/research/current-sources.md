## Payment / signing provider notes (P8/P9)

Per `handoff-archive-2026-09-02/docs/program/full-product-workstreams.md:90` + §8:

- Internal architecture (`crates/ptf-contracts/proto/ptf/contracts/v1/payment.proto`, `bounded_executor.proto`, `credential.proto`, `adapters/*` contracts, `sdks/*`, `hosted/operation-executor` isolation, `conformance/*` runners, negative/malformed corpus) is **never** deferrable because the real provider is unavailable.
- Allowed EXTERNAL-DEFERRED reason: vendor/provider sandbox or production account approval; platform entitlement/hardware fleet; legal/regulatory approval; or standard body has not published final artifact.
- Required deferral packet (§8.2) before marking EXTERNAL-DEFERRED: canonical adapter contract + version/maturity metadata; deterministic synthetic provider/recipient + resettable fixtures; captured official test vectors (pinned `manifest.json`); conformance runner targeting synthetic and real endpoints without changing trust-core semantics; negative cases (auth/replay/mutation/revoke/status/error/injection/timeout/retry/canary); explicit unsupported/security-claim text with owner/date/recheck trigger in profile doc.
- Closure (§8.3) requires account identifier/scope, provider/platform/profile version, dated real-endpoint conformance output linked to same vectors, custody/data-flow evidence, failure/revoke/replay/mutation/idempotency/canary results, independent review of deviations, human legal/cost acceptance, and updated ledgers/profile docs.
- For G5: at least one non-deferred production P8 payment profile **and** an exactly-one selection of either a certified non-deferred production P9 signing profile **or** a certified non-deferred production P9 action profile via `conformance/signing/p9-production-selection.json`. The unselected branch neither runs nor fails G5 but must still have emulator evidence.
