# x402 2.22.0 Python API Verification — 2026-09-04

## Summary

Plan 02 targets x402 `2.22.0`. Primary-source verification confirms the V2 schema and EVM exact client APIs used by PTF, and identifies one invalid constructor in the earlier plan: `x402Client(spend_controls=False)` is not supported by 2.22.0. The correct sequence is `x402Client()`, `set_spend_controls(False)`, then exact-network `register(...)`.

## Verified API facts

### V2 request types

`PaymentRequirements` fields are:

```python
scheme: str
network: Network
asset: str
amount: str
pay_to: str
max_timeout_seconds: int
extra: dict[str, Any]
```

`PaymentRequired` fields are:

```python
x402_version: int = 2
error: str | None
resource: ResourceInfo | None
accepts: list[PaymentRequirements]
extensions: dict[str, Any] | None
```

A deterministic reference fixture can therefore use:

```python
from x402.schemas.payments import PaymentRequired, PaymentRequirements, ResourceInfo

requirements = PaymentRequirements(
    scheme="exact",
    network="eip155:84532",
    asset="0x036CbD53842c5426634e7929541eC2318f3dCF7e",
    amount="2500000",
    pay_to="0x1111111111111111111111111111111111111111",
    max_timeout_seconds=60,
    extra={"name": "USDC", "version": "2"},
)

payment_required = PaymentRequired(
    x402_version=2,
    resource=ResourceInfo(url="https://merchant.example/protected"),
    accepts=[requirements],
    extensions={},
)
```

### Client construction

`x402Client.__init__` accepts only an optional `payment_requirements_selector`; spend controls are configured later through `set_spend_controls(...)`.

Verified reference construction:

```python
from x402 import x402Client
from x402.mechanisms.evm.exact import ExactEvmScheme

client = x402Client()
client.set_spend_controls(False)
client.register(
    "eip155:84532",
    ExactEvmScheme(signer=signer),
)
payload = await client.create_payment_payload(payment_required)
```

The earlier form:

```python
x402Client(spend_controls=False)
```

is invalid for this source version and is superseded in the PTF plan set.

### Signer contract

The minimum EVM client signer interface is:

```python
@property
def address(self) -> str: ...

def sign_typed_data(
    self,
    domain: TypedDataDomain,
    types: dict[str, list[TypedDataField]],
    primary_type: str,
    message: dict[str, Any],
) -> bytes: ...
```

`ExactEvmScheme` auto-wraps `eth_account` local accounts where available but also accepts any object implementing the signer protocol.

### Spend-control interpretation for PTF

x402's spend controls are client-side filtering/defense-in-depth. PTF does not use them as an authority source. The reference PTF executor explicitly disables them with `set_spend_controls(False)` so PTF Hard Policy + Standing Grant / Exact Human Approval remains the sole canonical authorization decision. This is an engineering choice consistent with the verified API; it is not a claim that x402 spend controls are unsafe.
